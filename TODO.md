## Plan: Per-gamePlayer Overlay Settings in DB

**TL;DR**: Remove overlay settings from the Twitch Extension broadcaster config and move them into the database — 4 nullable columns on `game_player` (per-player) and `game` (for DM). The extension API resolves the right overlay for the current broadcaster server-side. The web editor gets overlay sliders per player and at the game level.

---

**Phase 1 — DB Schema + Migration**
1. Add `overlayOffsetX`, `overlayOffsetY`, `overlayRadius`, `overlayTokenSize` (all `real`, nullable) to the `gamePlayer` table in schema.ts — *parallel with 2*
2. Add the same 4 columns to the `game` table in schema.ts (used for DM/host overlay) — *parallel with 1*
3. Create a new Drizzle migration SQL file (`drizzle/0002_...sql`) with `ALTER TABLE` for both tables

**Phase 2 — Shared Types** *(parallel with Phase 1)*
4. Add `ExtensionOverlaySettings = { offsetX, offsetY, radius, tokenSize }` to web.ts; add `broadcasterOverlay: ExtensionOverlaySettings` to `ExtensionGame`
5. Remove the `overlay: { ... }` field from `TwitchExtensionConfigContent` in extension.ts — keep only `gameOwner?: string`

**Phase 3 — Web API** *(depends on 1–4)*
6. [/api/extension/game/[id]/+server.ts](packages/web/src/routes/api/extension/game/[id]/+server.ts): after fetching the game, resolve `broadcasterOverlay` — look for a gamePlayer whose `player.createdBy == owner.id`; if found use that player's overlay columns (falling back to defaults for nulls); if not (DM case) use game-level overlay columns; always return a fully resolved `broadcasterOverlay` object
7. [/api/games/[id]/players/[playerId]/+server.ts](packages/web/src/routes/api/games/[id]/players/[playerId]/+server.ts): extend `PatchGamePlayerSchema` with 4 optional nullable overlay fields
8. [/api/games/[id]/+server.ts](packages/web/src/routes/api/games/[id]/+server.ts): extend game PATCH schema to accept game-level overlay fields; update `updateGame` in actions.ts if needed

**Phase 4 — Web Editor** *(parallel with Phase 5, depends on 3)*
9. Players.svelte (editor): add expandable "Nastavení overlay" section per player row with 4 sliders (same ranges as the extension Settings panel: offsetX/Y ±50, radius 10–60, tokenSize 3–20); on change PATCH the player
10. General.svelte (editor): add "Overlay pro DM" sliders at the bottom for the game-level overlay; on change PATCH the game

**Phase 5 — Extension** *(parallel with Phase 4, depends on 2)*
11. preference.svelte.ts: replace local `ViewerOverlaySettings` type with imported `ExtensionOverlaySettings` from shared
12. config.ts: remove `overlay` from `parseConfig` return/defaults; keep only `gameOwner` handling
13. twitch.svelte.ts: stop parsing `overlay` from Twitch broadcaster config
14. Settings.svelte (panel): replace `twitchStore.broadcasterConfig?.overlay` with `game.data?.broadcasterOverlay ?? DEFAULT_OVERLAY`
15. OverlayAnchor.svelte: replace `broadcasterConfig.overlay` with `gameData?.broadcasterOverlay ?? DEFAULT_OVERLAY`; remove `twitchStore`/`broadcasterConfig` refs if fully unused

---

**Relevant Files**
- schema.ts — add overlay cols to `gamePlayer` + `game`
- web.ts — `ExtensionOverlaySettings`, `ExtensionGame.broadcasterOverlay`
- extension.ts — remove `overlay` from `TwitchExtensionConfigContent`
- [/api/extension/game/[id]/+server.ts](packages/web/src/routes/api/extension/game/[id]/+server.ts) — resolve broadcaster overlay server-side
- Players.svelte (editor) — per-player overlay sliders
- General.svelte (editor) — game-level (DM) overlay sliders
- OverlayAnchor.svelte + Settings.svelte — use game data overlay

---

**Verification**
1. `pnpm -r build` — zero TS errors
2. `pnpm --filter web db:generate` + `db:migrate` — migration runs cleanly
3. Web editor: set per-player sliders → confirm PATCH saves → reload → values persist
4. Extension overlay: game with a player linked to the channel owner → overlay uses that player's DB settings
5. Extension overlay (DM case): channel owner not a gamePlayer → game-level overlay applied
6. Settings panel: viewer override still overrides DB settings; reset reverts to `broadcasterOverlay` from game data

---

**Decisions**
- `broadcasterOverlay` is always fully resolved (defaults applied server-side) — extension never needs fallback logic
- `TwitchExtensionConfigContent.overlay` fully removed — no backward compat concern
- `gameOwner` in Twitch config stays (needed to point the extension at another user's game)
- DM overlay stored as columns on `game` table (no separate table)
